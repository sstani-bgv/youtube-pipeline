# Groq Transcribe

Выполнять два этапа: raw ASR через Groq → контекстная проверка текста.

## Конфиденциальность

- До первого запуска ясно сообщить, что аудио будет отправлено в Groq API.
- Если пользователь не разрешал облачную обработку конфиденциального файла,
  остановиться и предложить локальный транскрибатор.
- Никогда не печатать, не логировать и не передавать `GROQ_API_KEY`.
- Не принимать API key в командной строке: shell history и process list могут его
  сохранить.
- Читать ключ только из `GROQ_API_KEY` окружения или из явно указанного env-файла.

## Вход

- локальный путь к аудио или видео;
- язык ISO-639-1 (`ru`, `en`, …) либо `auto`;
- каталог результата;
- при наличии: подпись, brief, список имён и терминов, соседний контекст.

Если путь или язык очевидны, не задавать лишних вопросов. Если цель не указана,
сохранить raw-файлы и `clean.txt` рядом в отдельном каталоге `<stem>-transcript`.

## Stage 1 — Raw ASR

Запустить:

```bash
uv run --with requests==2.34.2 \
  "<skill-dir>/scripts/transcribe_groq.py" \
  "<media-file>" \
  --output-dir "<output-dir>" \
  --language ru
```

Для автоопределения языка:

```text
--language auto
```

Для терминов можно подготовить обычный UTF-8 файл и передать:

```text
--prompt-file "<path-to-prompt.txt>"
```

Скрипт:

- извлекает выбранную аудиодорожку через `ffmpeg`;
- сжимает её в 16 kHz mono MP3;
- режет длинную запись на управляемые чанки;
- отправляет только аудиочанки в Groq;
- сшивает word timestamps с offset исходного файла;
- повторный запуск пропускает свежий результат, если нет `--force`.

Результат:

```text
output/
├── raw.words.json
├── raw.srt
├── raw.txt
└── raw.json
```

Не удалять raw-файлы до завершения проверки.

## Stage 2 — Context-aware fix

1. Прочитать `raw.txt`, `raw.srt` и доступный контекст.
2. Прочитать `references/GLOSSARY.md`. Пользовательский glossary рядом с проектом
   имеет приоритет над общим.
3. Составить маленькую таблицу вероятных замен: raw → корректно → основание.
4. Исправлять только то, что подтверждается контекстом, glossary или очевидной
   орфографией имени/термина.
5. Удалять технический мусор распознавания: повтор одного фрагмента, пустые
   междометия и обрывки, только если смысл не теряется.
6. Не сглаживать разговорную речь, мат, метафоры, длинные фразы и обращения.
7. Числа исправлять только при наличии источника. Иначе оставить как распознано и
   пометить сомнение в отчёте, не внутри чистого текста.
8. Сохранить `clean.txt`. Для длинного видео дополнительно создать `clean.md` с
   смысловыми разделами, не меняя порядок речи.

## Правила сохранения голоса

Не менять:

- просторечие и авторские слова;
- эмоциональную лексику;
- лёгкий мат;
- порядок аргументов;
- личные обращения;
- факты, которые нельзя проверить по контексту.

Если после очистки удалено больше 20% слов, перечитать diff: вероятно, это уже
редактура, а не исправление ASR.

## Проверка

Перед завершением:

1. Убедиться, что `raw.words.json` непустой.
2. Проверить начало, середину и конец SRT по таймкодам.
3. Убедиться, что `clean.txt` не стал литературнее исходной речи.
4. Перечислить пользователю исправленные имена/термины и сомнительные числа.
5. Сообщить модель, язык, длительность и пути к результатам.

## Ошибки установки

Если не найден Groq key, `ffmpeg`, `ffprobe` или `uv`, полностью прочитать
`references/SETUP.md` и дать точную команду для ОС пользователя.
